# Известные проблемы и технический долг

Актуально на 2026-10-30, после среза технического долга (ветка `refactoring/tech-debt`). Перед тем как опираться на пункт, стоит перепроверить его по коду.

Что сознательно вне области бандла (паблики, анонимные игроки, нераспарсенные матчи OpenDota), — в [api-coverage.md](api-coverage.md) → «Область бандла». Особенности данных источников (текущее имя команды у STRATZ, нераспарсенные матчи STRATZ, медленный режим с байбеками) — там же, в «Особенностях данных».

## STRATZ

- **Лимитер действует в пределах одного процесса.** `dota2_api.stratz.rate_limit` (`ClientConfig::rateLimitPerMinute`) — `ThrottlingHttpClient` со скользящим окном на `InMemoryStorage` в `StratzHttpClientFactory`. Каждый PHP-процесс (воркер Messenger, FPM-воркер, CLI) считает свой лимит: N воркеров вместе делают до N × `rate_limit` запросов в минуту. Общего лимита на несколько процессов (хранилище в cache/lock) нет — при нескольких воркерах `rate_limit` нужно делить на их число. По умолчанию лимитер выключен (`null`): превышение 150/мин даёт 429 → ретраи → `SourceRequestException` в `getError()`.
- **`getMatchesByTeam()` — только последние 100 матчей.** `TeamQuery::MATCHES` запрашивает `matches(request: {take: 100, skip: 0})`, а OpenDota `teams/{id}/matches` отдаёт всю историю (у Xtreme Gaming — 1143 матча = wins + losses, проверено 2026-10-30). Списки двух источников несопоставимы по длине; пагинации по `skip` в бандле нет.

## У потребителя (`dota2-analytical-service`)

- **Бандл 2.0 ломает его импорты.** Совместимость сознательно не сохранялась: классы переехали (`Domain\*` → `OpenDota\Match\*` / `OpenDota\Team\*` / `SharedKernel\*`, `Infrastructure\Exceptions\*` → `Exception\*`), порты переименованы (`MatchSourceInterface`, `TeamSourceInterface`), `getError()` — `?Dota2ApiExceptionInterface`, вместо `$client->matches()` / `teams()` — `$client->openDota()->matches()` / `teams()`; резолвера ролей OpenDota больше нет (сервис из DI удалён, роль — `position_est`). Потребитель подключает `dev-main` (теперь `2.0-dev`) и автовайрит `Dota2ApiClient` — при обновлении править `use`, вызовы клиента и, если он переопределяет сервисы бандла, их id. Бандл требует Symfony `^7.1`. `packages/test` ломается так же (`new Dota2ApiClientBuilder($http, ?ClientConfig $openDota, ?ClientConfig $stratz)`, `ClientConfig` без `ApiSource`).
- **Конфиг в старом формате больше не собирается.** Корневые `dota2_api.base_url` / `api_key` (и `source`) удалены — контейнер падает с `InvalidConfigurationException` («Unrecognized option»). Перед обновлением перейти на `dota2_api.opendota.{base_url, api_key}`; для STRATZ — `dota2_api.stratz.token` (и при желании `rate_limit`).
- `FetchMatchFromApiHandler` не читает `getError()`, а при `null` бросает общее «Match detail is null». Реальная причина (HTTP-ошибка или `SourceDataException` маппинга) теряется в логах.
- В `config/services.yaml` есть ссылки на `Domain\Services\RegionResolverInterface` и `Infrastructure\Services\RegionResolver`. В бандле таких классов нет.

## Исправлено

- **Технический долг после STRATZ (2026-10-30).** `KDA::getCoefficient()` = `round((kills + assists) / max(1, deaths), 2)` (были неверные скобки и деление на ноль). Эвристика ролей OpenDota удалена: роль — только `position_est`, иначе `UNKNOWN`; ушли `RoleResolverInterface`, `PrefilledRoleResolver`, `ProSceneRoleResolver` (с ошибками «нет мида», «две HARD_SUPPORT» и мёртвыми `assertLane*`), `MatchDetail::withResolvedRoles()`, `TeamSide::withPlayers()`, `MatchPlayerPerformance::withRole()`. Неиспользуемые `HttpStatusCode::TOO_MANY_REQUESTS` / `INTERNAL_SERVER_ERROR` удалены. Symfony `^7.1` (6.4 больше не поддерживается), зависимости обновлены, `composer audit` чистый. Окно параллельных запросов вынесено в общий `Infrastructure\Http\ConcurrentRequests` (было скопировано в оба источника). STRATZ: необязательный лимитер `dota2_api.stratz.rate_limit`; режим `getMatches(..., withPlaybackData: false)` — 5 матчей на запрос; `getPlayersByTeam()` / `getHeroesByTeam()` считают по всей истории команды (`TeamQuery::GROUP_BY_TAKE = 20000`), а не по окну последних ~100 матчей.
- **Источники как bounded contexts + STRATZ (2026-10-30).** `OpenDota/` и `Stratz/` — отдельные модели, общий словарь в `SharedKernel`; переключатель `source`, `SourceFactoryInterface`, `ApiSource`, `ClientConfigurationException` и корневые `base_url`/`api_key` удалены. STRATZ реализован: матчи (`getMatch`, `getMatches`) и команды (4 метода), без подстановки нулей вместо недоступных показателей.
- **Рефакторинг по контекстам DDD (2026-10-30).** HTTP-ошибка одного матча в `getMatches()` больше не роняет генератор — она приходит `SourceRequestException` в `getError()`, поток идёт дальше (включая обрыв и таймаут чанка). `getMatches()` параллелится с первого запроса: `ApiGateway::request()` ленивый, статус проверяет `decode()`. `MatchExtractor` работает с декодированным массивом и не даёт warning на отсутствующих ключах (нет ключа → `null`, обязательность проверяет `MatchMapper`); битый JSON → `SourceDataException`. Все исключения реализуют `Dota2ApiExceptionInterface`. Подробности — architecture.md.
- **Проверка полей источника (2026-10-30).** `getPlayersByTeam()` падал на бывших игроках (`name` / `is_current_team_member` = `null`). `getTeams()` падал на командах с пустым `tag`. Удалена пустая фикстура `team_responses.json`.
- **Рефакторинг 2026-10-11** (по [refactoring-plan.md](refactoring-plan.md)). `dd()` в `getMatch()`; `TeamName(null)` / `TeamId(null)`; лесные линии и `lane_role`; ретраи 429/5xx; тип таймаута; подмена `http_client` приложения; двойной граф DI и двойная регистрация `RoleResolverInterface`; зависимость домена от инфраструктуры (`MatchResult`); `ApiGateway` на конкретном классе; `PlayerProviderInterface` и `ProviderException` удалены; `toCollection()`, возвращавший `[]`, удалён; схема `phpunit.xml.dist`; `strict_types` везде.
